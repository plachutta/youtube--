## 4. Open and inspect the project in Kdenlive

### Kdenlive Launch

**PASS** - Kdenlive 25.12.3 launches successfully in an isolated kwin-mcp virtual KWin session.

**Launch command**:

```python
sess = s.Session()
info = sess.start()
app_info = sess.launch_app(['kdenlive', '--no-welcome'])
```

**Kdenlive session evidence**:

- Kdenlive process stays running during the session
- PID recorded during launch (e.g., PID 146855, 149332, 155243, etc.)
- App log shows: SHOWING WELCOME!!!!!!, CREATING SPLASH SCREEN SPLASH, QDBusError for portal registration (expected in isolated session)
- Kdenlive closes when sess.stop() is called: "Kdenlive still running after stop: False"

### Project Inspection

**BLOCKED** - The kwin-mcp AT-SPI accessibility tree does not surface Kdenlive UI elements on Wayland. The tree contains 223 elements from the host session (ksmserver, gmenudbusmenuproxy, etc.), but Kdenlive-specific UI elements are not identifiable through the accessibility interface.

**Evidence**:

- from kwin_mcp.accessibility import get_accessibility_tree() returns 223 elements
- Kdenlive-related name search yields 0 elements
- Application-level elements show host-session processes, not Kdenlive UI
- X Error "BadWindow (invalid Window parameter)" in melt logs indicates Kdenlive's Window ID is not accessible through the current D-Bus configuration

**Workaround attempted**:

- kdenlive --no-welcome flag used to skip welcome screen
- EISClient keyboard input attempted (Ctrl+N, Ctrl+S, etc.)
- Keyboard key events sent without errors, but UI effect not verifiable through accessibility tree
